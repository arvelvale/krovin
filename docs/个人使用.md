# 个人使用：面板常驻节点，本机只维持一条反向隧道

评审时用的 `serve-for-judges.bat` 要同步代码、挂公网、断线重启面板，个人用不需要这些。个人用只要两件事：

1. **面板常驻在节点上**（tmux 会话 `krovin`，只听 `127.0.0.1`，不上公网）——本机关机它也在；
2. **本机维持一条反向隧道**：节点上的 JEV / Linear 请求经它走本机代理出境（节点直连不了境外）。

## 第一次 / 更新代码后

双击 `krovin-panel.bat`：同步代码 → 重启节点上的常驻面板。需要 `.env` 里有固定的 `AGENT_WEB_TOKEN`。

## 每天

双击 `krovin-tunnel.bat`，窗口保持打开，浏览器打开 <http://127.0.0.1:9000>（本机端口转发到节点面板）。

- 需要本机代理（mihomo）在运行，默认 `127.0.0.1:10090`（`HTTPS_PROXY` 可改）。
- 隧道断了会自动重连（首次重连可能要等十几秒，让节点释放旧连接）。
- 关掉窗口：JEV 和 Linear 暂时不可用（技能选择退回主模型自选，写操作全部改为人工确认），聊天、改代码、跑测试照常；重新打开窗口后自动恢复，**不用重启面板**。
- 隧道用的是节点上的**固定端口 10090**，常驻面板的 `https_proxy` 就指向它；评审服务（`serve-for-judges`）用的是随机端口，两者互不干扰，但都要占用节点的 9000 端口，不能同时开。

## 命令行等价

```bash
python scripts/node.py sync                    # 只同步代码
python scripts/node.py daemon start [--sync]   # 起常驻面板；stop / status / logs
python scripts/node.py tunnel                  # 反向隧道 + 本机 9000 转发
```

`daemon status` 会告诉你三件事：面板进程在不在、面板能不能访问、隧道连没连。
换端口：`--port`（节点上面板端口，默认 9000）、`--remote-port`（隧道端口，默认 10090，daemon 与 tunnel 要一致）。

## 和评审模式的区别

| | 个人使用 | 评审（serve-for-judges） |
|---|---|---|
| 面板进程 | 节点 tmux 常驻，不随本机连接结束 | 挂在本机 SSH 连接上，断线即退出并重启 |
| 监听 | 127.0.0.1（本机转发访问） | 0.0.0.0（公网映射） |
| 同步代码 | 需要时手动 | 每次启动都同步 |
| 隧道端口 | 固定 10090 | 随机 |
