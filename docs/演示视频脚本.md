# 演示视频脚本：用 KROVIN 从零做完「番茄钟」

成品 7 分钟以内。全程只做一件事：**把一个 Linear issue 拆成 6 个子任务，逐个实现，最后在浏览器里用起来**。
下面每一步的操作、要粘贴的提示词、画面上必须出现的东西都写死了，照做即可，不需要再选择。

## 0. 项目：番茄钟（纯前端，双击 index.html 就能用）

| 项 | 内容 |
|---|---|
| 功能 | 专注 25 分钟 → 短休息 5 分钟；每完成 4 个专注后，长休息 15 分钟；开始 / 暂停 / 重置；任务清单（添加、删除、勾选完成）；每完成一个专注，给当前任务的番茄数 +1；统计今天完成了几个专注、共多少分钟，以及最近 7 天每天的专注数（柱状图）；数据存在浏览器 localStorage，刷新不丢；空格键开始 / 暂停 |
| 文件（agent 最终会写出这些） | `src/storage.js` `src/timer.js` `src/tasks.js` `src/stats.js` `src/main.js` `index.html` `style.css` `tests/storage.test.mjs` `tests/timer.test.mjs` `tests/tasks.test.mjs` `tests/stats.test.mjs` `README.md` |
| 验证方式 | 沙箱里执行 `node --test`，4 个测试文件全部通过；浏览器里点开产物卡片手动用一遍 |
| 不使用 | npm、TypeScript、任何框架（沙箱里 npm install 整套构建工具目前会超时，已实测，所以这个项目不依赖它） |

## 1. 录制前准备（不上镜，按顺序做，约 15 分钟）

1. **启动服务**：双击 `krovin-tunnel.bat`（窗口保持打开）。如果节点上面板没在跑，先双击 `krovin-panel.bat`。评审用的 `serve-for-judges.bat` 占着节点 9000 端口时，个人模式起不来，先关掉它。
2. **确认灯**：浏览器打开 `http://127.0.0.1:9000` 登录后，左下角「主力」「难题」「JEV 决策」「Linear」四个灯是绿色，「备用」是蓝色。任何一个不是，先不要录。
3. **在 Linear 里建项目和 issue（用你自己的账号，团队 DAY）**：
   - 新建项目，名字：`Pomodoro 演示`。
   - 在这个项目里新建 issue，标题：`番茄钟应用`，描述粘贴下面这段原文：

     ```
     做一个纯前端的番茄钟网页应用，双击 index.html 就能用，不依赖 npm 和任何框架。
     功能：
     1. 专注 25 分钟，短休息 5 分钟；每完成 4 个专注后长休息 15 分钟。
     2. 开始、暂停、重置；空格键开始或暂停。
     3. 任务清单：添加、删除、勾选完成；每完成一个专注，当前任务的番茄数加 1。
     4. 统计：今天完成的专注个数、总专注分钟数；最近 7 天每天的专注个数，用柱状图显示。
     5. 数据保存在浏览器 localStorage，刷新页面不丢。
     验收：node --test 全部通过；浏览器里手动走一遍上述功能。
     ```
4. **接入 Linear（不上镜）**：面板左栏「集成设置」→ 粘贴你的 Linear API Key → 点「连接并读取团队 / 项目」→ 团队选 `DAY`，项目选 `Pomodoro 演示` → 保存。**这一步的下拉里会出现你所有项目名，绝对不要录进去。**
5. **新建工作空间**：输入框下面的工作空间选择器 → 新建工作空间 → 名字填 `pomodoro` → 创建 → 设为当前。
6. **清屏**：左栏「最近对话」里把旧对话全部删掉（悬停出现垃圾桶）。
7. **录屏设置**：OBS，画面 1920×1080，30 帧；浏览器缩放 125%；关掉其它窗口和通知；地址栏不要露出口令。
8. **权限**：输入框下面的权限选择器保持「默认权限」，第 2 步（拆分）开始录。

## 2. 分镜与提示词（一共 9 条，每条单独一轮；每条之间停录，分段录）

> 每条提示词整段复制粘贴，回车发送。发送后不要再输入任何东西，等这一轮结束（回复出现、输入框恢复可用）再进入下一条。

### 镜头 1｜开场（0:00–0:25，不发提示词）
- 画面：主界面，鼠标依次停在左下角 4 个绿灯、输入框下方的「pomodoro」和「默认权限」。
- 旁白：「KROVIN 跑在 DGX Spark 上。主力模型是本地的 Nemotron，难题交给云端 step-5，所有『选哪个』的判断交给 JEV。现在让它从零做一个番茄钟。」

### 镜头 2｜拆分（0:25–1:50）
提示词 1：
```
读取 Linear 项目「Pomodoro 演示」里标题为「番茄钟应用」的 issue，把它拆成 6 个子任务：1 存储模块；2 计时器逻辑；3 任务清单；4 统计；5 界面；6 收尾与测试。每个子任务写明验收标准，然后在 Linear 里作为该 issue 的子任务创建。
```
- 画面必须出现：右侧轨迹里 JEV 选中 `issue-breakdown`；先回复一张子任务表；然后 Linear 创建的确认卡，卡片第一行是人话（「在 Linear 上新建 issue 「存储模块」，作为 … 的子任务」）。
- 操作：前两张确认卡手动点「同意执行」；第三张出现时，点输入框下面的权限选择器 → 选「全自动」（已经弹出的卡片会自动通过，剩下的 3 个由 JEV 自动决定）。
- 旁白：「前两张我手动确认，让大家看到每一步都会说清楚要做什么。现在切到全自动，剩下的交给 JEV 判断。」
- 结束标志：回复里列出 6 个新建的子任务；到 Linear 网页刷新能看到这 6 个（录 3 秒 Linear 页面）。

### 镜头 3｜计划（1:50–2:20）
提示词 2：
```
为「番茄钟应用」写实施计划，保存到 docs/plans/pomodoro.md。内容包括：每个源码文件的职责、每个模块导出的函数名和参数、测试文件清单、验收命令 node --test。
```
- 画面必须出现：`plan-writer` 被选中；回复末尾给出文件路径 `docs/plans/pomodoro.md`。
- 旁白：「先写计划，后面每一步都按这份计划来。」

### 镜头 4–7｜逐个实现 4 个模块（2:20–4:30，每个 30–40 秒，等待部分快放）
提示词 3（存储）：
```
实现子任务「存储模块」：新建 src/storage.js，导出 createStorage(backend)，backend 只需要 getItem(key) 和 setItem(key, value) 两个方法（与 localStorage 兼容）。返回对象有 load(key, fallback) 和 save(key, value)：save 用 JSON 序列化；load 在键不存在或内容不是合法 JSON 时返回 fallback。新建 tests/storage.test.mjs，用一个内存对象当 backend，写 3 个用例：正常读写、键不存在、内容损坏。在沙箱里运行 node --test，全部通过后提交，提交说明写中文。
```
提示词 4（计时器）：
```
实现子任务「计时器逻辑」：新建 src/timer.js，全部是纯函数，导出：createTimer(config)，config 默认 {focusMin:25, shortMin:5, longMin:15, longEvery:4}，返回状态 {phase:"focus", remaining:1500, running:false, completedFocus:0, config}；start(state)、pause(state)、reset(state) 各返回新状态；tick(state, seconds) 在 running 为 true 时减少 remaining，减到 0 时自动进入下一阶段：专注结束后 completedFocus 加 1，如果 completedFocus 能被 longEvery 整除进入 "long"，否则进入 "short"；休息结束回到 "focus"；进入新阶段时 running 保持 true，remaining 设为该阶段的秒数。新建 tests/timer.test.mjs，写 8 个用例：初始状态、start、pause、reset、tick 减时间、专注结束进短休息、第 4 个专注结束进长休息、休息结束回到专注。在沙箱里运行 node --test，全部通过后提交，提交说明写中文。
```
提示词 5（任务清单）：
```
实现子任务「任务清单」：新建 src/tasks.js，全部是纯函数，任务对象是 {id, title, done, pomodoros}。导出：addTask(list, title)——title 去掉首尾空格，为空或超过 60 个字符时返回原列表，否则返回新列表，id 取现有最大 id 加 1（空列表从 1 开始），done 为 false，pomodoros 为 0；removeTask(list, id)；toggleDone(list, id)；addPomodoro(list, id) 让该任务的 pomodoros 加 1。新建 tests/tasks.test.mjs，写 6 个用例：添加、空标题被拒绝、超长标题被拒绝、删除、勾选切换、番茄数加 1。在沙箱里运行 node --test，全部通过后提交，提交说明写中文。
```
提示词 6（统计）：
```
实现子任务「统计」：新建 src/stats.js，全部是纯函数，统计数据是对象 {"2026-09-29": {count: 2, minutes: 50}} 这种按日期（YYYY-MM-DD）存的结构。导出：recordFocus(stats, dateISO, minutes)，该日期的 count 加 1、minutes 加上 minutes，返回新对象；today(stats, dateISO) 返回 {count, minutes}，没有记录时返回 {count:0, minutes:0}；last7(stats, dateISO) 返回长度为 7 的数组，元素是 {date, count}，从 6 天前到 dateISO 当天，按日期从早到晚排列，没有记录的日期 count 为 0。新建 tests/stats.test.mjs，写 5 个用例：记录一次、同一天记录两次累加、today 无记录、last7 长度和顺序、last7 跨月份（dateISO 取 2026-10-02）。在沙箱里运行 node --test，全部通过后提交，提交说明写中文。
```
- 每条的画面必须出现：右侧轨迹里 `run_in_sandbox` 的调用；回复里「node --test」的通过数量；`git_commit` 的提交记录。全自动开着，不会有确认卡。
- 旁白（4 条各说一句）：「第一个模块，存储。」「第二个，计时器，纯函数，好测试。」「第三个，任务清单。」「第四个，统计。每个模块都是在隔离沙箱里跑测试、通过才提交。」

### 镜头 8｜界面（4:30–5:30）
提示词 7：
```
实现子任务「界面」：新建 index.html、style.css、src/main.js，把 src 下的 4 个模块接起来。页面包含：顶部显示当前阶段（专注 / 短休息 / 长休息）和 MM:SS 倒计时，下面是「开始」「暂停」「重置」三个按钮；中间是任务清单（输入框加「添加」按钮，每项有勾选框、标题、番茄数、删除按钮，点击标题把它设为当前任务，当前任务高亮）；下面是统计区：今天完成 N 个专注、共 M 分钟，以及一个 canvas 柱状图显示最近 7 天每天的专注个数。每秒调用一次 tick；专注阶段结束时，给当前任务调用 addPomodoro，并调用 recordFocus 记录 25 分钟。任务列表和统计数据用 createStorage(localStorage) 保存，页面加载时读取。按空格键开始或暂停。页面标题显示剩余时间。main.js 用 <script type="module"> 引入，不使用任何框架。写完后在沙箱里运行 node --check src/main.js，通过后提交，提交说明写中文。
```
- 画面必须出现：回复下面出现产物卡片（`index.html`）。
- 操作：点卡片上的「▶」，大窗口里预览：① 在输入框添加任务「写周报」；② 点它的标题设为当前任务；③ 点「开始」，倒计时从 25:00 开始走；④ 按空格暂停；⑤ 点「重置」。每一步停留 2 秒。
- 旁白：「agent 没有浏览器，所以它验证了语法和逻辑；界面的样子和手感，这里我们自己点一遍。」

## 4. 出问题时的固定处理（每种情况只有一个动作）
| 现象 | 动作 |
|---|---|
| 某一轮回复里测试没有全部通过 | 在同一个对话里发送：`测试没有全部通过，请根据失败信息修复，修好后重新运行 node --test，通过后再提交。` |
| 某一轮 30 步用完仍没结束（回复里写着已达步数上限） | 在同一个对话里发送：`继续上一步没完成的部分，完成后运行 node --test 并提交。` |
| Linear 相关那一轮报错 | 检查左下「Linear」灯；灯是绿的就把同一条提示词原样再发一次；不是绿的先处理隧道再录 |
| 整段录坏了 | 只重录这一条：删除该对话，回到上一条结束时的状态重新发送同一条提示词（模块文件已提交到 git，不会丢） |
| 预览里页面空白 | 点预览窗口顶部「刷新」；仍空白就点「代码」，把报错信息粘给 agent：`预览页面空白，请检查 src/main.js 的 import 路径和语法，修好后重新运行 node --check。` |

## 5. 事先必须知道的限制
- 每一轮耗时约 3–5 分钟，9 条加等待共约 40 分钟，所以必须分段录再剪。
- 云端模型每一轮的输出有随机性，回复措辞和文件内容每次不同，脚本只固定了「发什么」和「必须出现什么」。
- 这套脚本我没有从头到尾跑过：拆分、写文件、沙箱跑 node 测试、预览、Linear 更新分别验证过，连起来没有。**录之前先按第 2 节把 9 条提示词完整跑一遍（不录屏），确认每条的「必须出现」都出现，再正式录。**
