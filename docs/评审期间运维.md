# 评审期间运维（团队内部）

评委只需要浏览器、地址和口令（见 `deliverables/评委使用指南.pdf`，由 `python scripts/make_guide.py` 生成）。
**但服务能不能用，取决于我们这边一台电脑一直开着一个窗口。** 这份清单说明为什么、怎么开、出问题怎么办。

## 为什么需要本机常驻

```
评委浏览器 ──> 节点公网入口 :9006 ──> 节点 0.0.0.0:9000（Web 面板 + agent）
                                              │
                                              ├── 本地模型（vLLM Nemotron / Ollama Qwen）、阶跃：节点直连
                                              │
                                              └── JEV、Linear（境外）：节点直连不了
                                                      │  SSH 反向隧道（节点 127.0.0.1:随机端口）
                                                      ▼
                                              团队电脑 127.0.0.1:10090（mihomo 代理）──> JEV / Linear
```

面板进程和反向隧道都挂在团队电脑发起的那条 SSH 连接上：

- 连接断了，面板随之退出（不会在节点上遗留无人管的公网服务）；
- 代理关了，JEV 和 Linear 不可用：技能选择退回主模型自选、写操作全部改为人工确认、Linear 工具报错。聊天、改代码、跑测试照常。

## 评审前一天

1. `.env` 里固定 `AGENT_WEB_TOKEN`（不固定每次启动随机生成，评委手里的口令会失效）。
2. 生成评委指南：`GUIDE_CONTACT="晨熠 · 微信 xxx" python scripts/make_guide.py`，把 `deliverables/评委使用指南.pdf` 放进提交材料。**这个 PDF 含口令，不要传到公开仓库或群聊以外的地方。**
3. 电脑电源设置（需要自己在系统里改）：插电、**合上盖子不睡眠**。启动脚本运行期间会阻止系统空闲睡眠，但管不了合盖。
4. mihomo 设为开机自启，确认规则放行 `api.typesafe.ai` 和 `api.linear.app`。
5. 前端有改动就先 `cd web && npm run build`。

## 启动

双击仓库根目录的 **`serve-for-judges.bat`**，它依次做三件事：

| 步骤 | 看什么 |
|---|---|
| 1/3 自检 | 本机代理、经代理连 JEV / Linear、SSH、口令、前端构建，全部 ✓ |
| 2/3 同步 + 节点自检 | `agent doctor`：本地主力、备用、云端、JEV、Linear、工作区全部 ✓ |
| 3/3 启动 | 出现「面板已启动：http://…:9006」 |

然后用手机或另一台电脑打开公网地址，输入口令，新对话里说一句「看看最近 3 条提交」，能回答就说明整条链路通了。

命令行等价写法：`python scripts/node.py preflight`，再 `python scripts/node.py serve --public --keep-alive`。

不用本机值守的等价做法：`python scripts/node.py daemon stop && python scripts/node.py daemon start --public`，面板直接在节点 tmux 里监听 0.0.0.0:9000，公网映射 :9006 常开（静态页 /demo、/essay、/report 免登录，工作台要口令），不依赖本机在线；代价是断线时代理自愈和防睡眠由节点侧承担。

## 运行中

- 窗口里每次断线重连都会打印一行；本机代理、公网入口的状态变化也会打印（不变不刷屏）。
- SSH 断开会自动重连（5 秒起，最长 60 秒一次），面板随之重启。登录态已落盘，评委不用重新输口令；断线那一刻进行中的对话会中断，重新发一句即可。
- 窗口运行期间电脑不会因空闲睡眠。

## 出问题怎么办

| 现象 | 处理 |
|---|---|
| 窗口被关了 / 电脑重启了 | 再双击 `serve-for-judges.bat` |
| 窗口提示「本机代理：不通」 | 打开 mihomo；恢复后不用重启窗口，下一次调用就会走通 |
| 一直「连不上节点」 | 网络或节点问题，脚本会自己重试；超过 10 分钟联系组委会 |
| 面板左下「主力」灯琥珀 | vLLM 挂了：SSH 上节点 `tmux attach -t vllm` 看日志，按 [节点连接与模型运维](节点连接与模型运维.md) 里的命令重启（冷启动约 5 分钟）。期间备用 Qwen 会顶上 |
| 评委说「修 bug 时它说已经修好了」 | 请评委点左下仓库名旁的「重置」 |
| 评委说「点重置提示有对话在进行」 | 有人正在跑任务，等几分钟 |

## 关于代码沙箱（OpenShell）

`run_in_sandbox` 依赖节点上的 OpenShell 网关（`~/openshell/bin/openshell-gateway --disable-tls --config ~/openshell/gateway.toml`，监听 127.0.0.1:17670）。它是手动拉起的进程，**节点重启后不会自动起来**。
评审前检查：`ssh` 上节点执行 `~/openshell/bin/openshell status`，应显示 Connected；`openshell sandbox list` 里应有 `spark-devflow`（首次调用会自动创建，约几秒）。网关没起时 agent 会收到「沙箱不可用」并换路，其它功能不受影响。
镜像 `ghcr.io/nvidia/openshell-community/sandboxes/base:latest`（4GB）已加载在节点 docker 里，不要 `docker image prune -a`。

## 关于「工作区与集成」

首次登录的人会看到「开始之前」向导（点「使用演示环境」即可，只弹一次）。面板是单实例：有人填了自己的 Linear Key、切了工作区，所有访问者都会受影响。
评委反馈「Linear 里找不到 DAY-298」「仓库不是 tinyledger」时，让 TA 在「集成设置」点「恢复演示」、在「工作区」把「演示（tinyledger）」设为当前；
或者节点上删掉 `~/dgx-agent/var/integrations.json` 后重启面板（同时清掉所有人填的 Key 和令牌）。

## 评审结束

1. 窗口里按 Ctrl+C（节点上的面板随之退出）。
2. 换掉 `AGENT_WEB_TOKEN`（换了之后旧登录全部失效）；按计划轮换 StepFun / TypeSafe / Linear 的 Key。
